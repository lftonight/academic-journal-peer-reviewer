# 防御性写作与交付门控

本文件与技能目录内的Python脚本共同使用。共享规则适用于中英文论文和其他写作成品，正文维持其读者、用途及作者语气。

## 1 表达规则

用具体主体和动作说明问题、做法、发现及已有价值。已确定事实直接陈述，推断、建议和未知使用真实力度。在论点完成处停止，不预设反对，不逐段追加通用防御语，也不改用空泛积极总结。

必要限定与对应对象、研究设计或主张自然相连；一般局限归入合适位置。段内已有信息可调整顺序，限定指向、引文归属和判断力度保持。不能通过删未知、删负面发现或变更主要结局消除防御口吻。

“可能”“提示”、may、might、suggest以及统计否定不是禁词。忠实翻译、逐字引用及用户明确要求保留的措辞，以准确为先。

## 2 上游适配

参考Adkid-Zephyr的[Anti-Defensive Writing](https://github.com/Adkid-Zephyr/anti-defensive-writing-Skill)，固定提交 `82d31402caa0db1790026824399044538483171b`。采用主张与证据对齐、明确真实价值、减少情绪性自贬和机械防御的思路。

上游关于重选主结果、更换评价维度、弱化实验或只呈现优势的建议，不用于本技能的语言润色。负面结果、失败、不良事件、未知及必要限制完整报告。不得为了叙事优势改变原有科学内容。许可与归属见[声明](../ATTRIBUTION.md)。

## 3 环境与文件

脚本相对于技能目录位于 `scripts/writing_gate.py`，仅依赖Python标准库，离线运行，不改正文、不联网、不调用API。

- Codex：使用已安装技能目录中的脚本；输出记录放在当前项目的私人工作目录。
- ChatGPT：从已安装插件或上传包中取得脚本和资源。具备Python且文件可访问时，用同一接口运行。需要解压时先识别技能根目录，不使用用户本机专用路径。
- 无Python或文件不可访问：如实说明缺口，继续阅读与审查准备，并转到能够执行检查的环境。不得伪称 `PASS` 或把未运行脚本的文本作为已通过强制门控的最终正文。

Word、PDF和PPT先提取最终可见文字并核对一致。只在聊天中交付的正文也保存临时UTF-8文本；不要求用户接收临时记录。门控后正文改变，旧审查记录立即失效。

## 4 准备审查

以下示例在技能目录下执行，正文与记录均位于当前项目的工作目录。按实际位置调整参数，路径可以是任意操作系统的有效绝对路径或相对路径。

```text
python -B scripts/writing_gate.py prepare --text WORK/2026-10-13_正文.md --review-out WORK/2026-10-13_写作审查.json
```

`WORK`表示用户本次项目的私人工作目录，并非包内目录。`prepare`退出0仅表示生成模板；状态仍为 `BLOCKED`，七项确认初始均为 `false`，不会自动放行。

阅读全文与候选句，修订无信息增量的套话。保留有实际含义的候选时，保持其ID、原句及规则不变，填写 `reason_type` 与具体 `explanation`。支持的理由类型为：

- `scientific_scope`：对象、范围或因果等科学边界。
- `uncertainty`：真实未知和不确定性。
- `statistical_or_negative_fact`：统计结论、负面结果或未完成事实。
- `journal_requirement`：明确的期刊或报告要求。
- `necessary_comparison`：实际必要的比较或概念辨析。
- `verbatim_quote`：必须准确保留的引用或原文。

不批量忽略，不把所有候选笼统解释为“科学需要”。修改正文后，重新为新文本生成记录。

## 5 语义审查与检查

实际检查后，逐项把 `checks` 中的值设为布尔值 `true`：

| 字段 | 实际核对内容 |
|---|---|
| `skill_loaded` | 已读取当前技能与门控规则。 |
| `content_preserved` | 原稿信息完整；起草内容有材料依据。 |
| `evidence_preserved` | 确定性、推断类型、范围和统计判断不变。 |
| `citations_preserved` | 引文仍支持对应主张，没有拼接或扩大。 |
| `no_selective_reporting` | 未遗漏负面结果、失败、未知或必要条件。 |
| `paragraph_endings_reviewed` | 段落自然收束，必要限定已妥善整合。 |
| `genre_preserved` | 保留正确文体、作者语气与用途。 |

起草任务按已有材料检查，不能因为没有原稿跳过事实与证据审查。

```text
python -B scripts/writing_gate.py check --text WORK/2026-10-13_正文.md --review WORK/2026-10-13_写作审查.json --report WORK/2026-10-13_门控报告.json
```

仅当 `check` 退出码为0且报告为 `PASS` 才交付。退出码1为 `BLOCKED`，2为 `ERROR`。没有关键词命中也要完成语义审查；缺审查、未处理候选、正文哈希变化或文件错误必须先解决。

## 6 记录与能力边界

记录包含原句及可能的研究信息，保存在私人工作目录，不上传到公开仓库。成品正文不加入哈希、自检表和工程说明。

`PASS`表示候选扫描和审查记录满足规则，语义确认仍由实际审查者负责。它不证明机器理解了全部文风，不核实审查理由，不保证科学正确或检测分数。宿主的全局前置要求由其指令或配置启用；安装插件本身不构成不可绕过的模型输出拦截器。
